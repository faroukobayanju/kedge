## Problem Statement

People let coding agents run unattended, and the agents fail silently. They don't crash. They drift: they touch unrelated files, break tests that used to pass, loop, or burn budget, and then report success. The hackathon tagline is "agents you'd trust to run without you watching." driftguard is the supervisor that makes that trust possible.

The test task is **turning failing Dependabot/Renovate PRs green**. Dependency bumps break builds every week, the PRs pile up red, and nobody wants to fix them. CI gives a binary verdict, so success can be measured.

## What Makes This Cool

- The agent has a live "rewind" moment. It catches its own silent failure, restores the last good state and retries, and the demo shows that happening.
- Both neatlogs judges named the pain this targets. Akshay: agents "quietly degrade instead of stopping". Ajay: he wants "a log of every change" and a recovery tip "in context on every step".
- Results are honest numbers, not vibes: "X of N red PRs turned green, M drifts caught, $Y per fixed PR."

## Constraints

- Two people and about 48 hours. Every commit must be dated within the hackathon window (Oct 10 12:30 PM IST to Oct 12 11:55 PM IST).
- **$0 budget.** Model spend comes from AWS Bedrock credits, which only go to the first 200 teams to check in (check-in opens Sat Oct 10, 3:30 AM GMT+1). The fallback is OpenCode with a free model.
- Required tools: neatlogs, Entire and cfo.ai.

## Recommended Approach

**Architecture**
- **Supervisor (Python, your own code).** Takes a red PR URL, clones it into a Docker container, reads the CI failure log, and writes a plan (which files may change and the expected fix).
- **Worker.** Headless Claude Code (`claude -p`, Bedrock via `CLAUDE_CODE_USE_BEDROCK=1`) with Entire hooks enabled. It runs one edit step at a time. Fallback worker: OpenCode with a free model. Both sit behind `run_edit_step()`.
- **Drift checks after every step**, all deterministic:
  - test pass count went down
  - diff touched files outside the plan
  - step cost pushed total spend over the budget
  - same action repeated (loop)
- **On drift:**
  1. `git reset --hard` to the last good commit.
  2. Add a one-line recovery note to the worker's next prompt.
  3. Retry.
  - Limits: 3 rollbacks or $0.50 per PR. When either runs out, stop and write a "couldn't fix" report explaining why.
- **On green:**
  1. Commit (Entire adds the `Entire-Checkpoint:` trailer).
  2. Push to the fork.
  3. Open a draft PR. Its body contains the run report, the `entire checkpoint explain` output, and neatlogs trace links.
- **Observability.** neatlogs Python SDK (`neatlogs.init()`). One span per supervisor step, each with custom attributes `{step, action, files, tests_passed, cost, drift_reason}`. After the run, the neatlogs public API (`/api/v1/public`) is used to pull numbers for the report.
- **`--chaos` flag.** Injects a plausible but wrong tool result, which makes before/after runs repeatable. "Before" = watchdog off: the bad PR ships. "After" = watchdog on: the drift is caught and recovered.
- **Interface.** CLI `driftguard run <pr-url> [--chaos] [--no-guard]`, a static HTML report per run, and a Markdown version in the PR body. No web app.

**Step record (the contract between the two people):**
`{run_id, step, action, files_changed, tests_passed, tests_total, cost_usd, drift: null|reason, checkpoint_sha}`

**Split**
- **Person A (core):** supervisor loop, Docker runner, worker adapter (Claude Code and OpenCode), drift checks, rollback, PR creation.
- **Person B (evidence and story):** neatlogs instrumentation, chaos harness, before/after runs, HTML/MD report, cfo.ai plan (price per green PR), the 6 #neatHack posts, and the demo video.

## Success Criteria

- At least 5 of 10 seeded red PRs turned green unattended.
- At least 1 recorded drift caught and recovered, with neatlogs trace links.
- A before/after pair from the `--chaos` run with numbers for success, cost and steps.
- Entire checkpoints on every agent commit.
- A cfo.ai plan covering pricing, costs, revenue and runway.
- 6 or more X posts tagged #neatHack, with the final post quoting the official neatlogs post.

## Distribution Plan

A public GitHub repo, installed with `pip install -e .` or `uvx driftguard`. The demo runs from the CLI. No hosting is needed.
